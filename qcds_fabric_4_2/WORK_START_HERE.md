## 6. Superintelligence research track — what to build next

The next track is not “claim ASI.” It is to test whether the QCDS architecture can acquire increasingly general, self-correcting inferential capability while preserving inspectability.

Build these as falsifiable capabilities:

### S1 — Relation invention

Expand beyond a fixed local predicate grammar. New relations must be proposed from unresolved structure, validated on held-out evidence and rejected when they fail. Keep provenance from the contradiction/question that caused each relation to be invented.

### S2 — Question invention / active inference

When present variables cannot stabilize the inference, generate explicit acquisition questions: missing variables, counterexamples, disambiguating observations and source requests. A generated question must alter the next executable inference boundary rather than remain commentary.

### S3 — Recursive oracle evolution

The return path must demonstrably alter conditions, representations, relations, oracle structure, rotation schedules and/or graph topology. Measure how much changes and whether those changes improve held-out performance without using audit truth for selection.

### S4 — Dynamic graph evolution

Permit bounded creation, contraction and re-expansion of parallel branches according to unresolved structure. Preserve explicit barriers, lineage, resource accounting and the distinction between logical Fabric width and coherent quantum state-space width.

### S5 — Cross-domain transfer

Use multiple synthetic domains with different surface representations but shared latent relations. Test whether invented relations or Syntract structures transfer without leaking generator truth. Include controls where transfer should fail.

### S6 — Long-horizon stability without confidence laundering

A high-amplitude answer must not count as convergence when rotational, exclusion, oracle, representation or substrate disagreement remains. Track stable core and sensitive shell separately across longer recursive horizons.

### S7 — External evidence boundary

Add real, externally sourced bounded tasks only after the synthetic audit discipline is solid. Keep discovery, validation and final audit separated. External evidence must not be treated as independent merely because it comes from another file if it shares the same underlying source.

### S8 — Substrate program

Preserve exact/classical emulation, noisy simulation and future hardware execution as separate evidence classes. Any future QPU result must state register size, mapping, shots, backend, transpilation, noise assumptions and whether any operation was genuinely coherent across lanes.
